C2C / CLI design / Swimlane

Two explicit connection profiles.

One installation, one read-only MCP endpoint, many registered workspaces. The CLI owns connection setup and diagnostics; ChatGPT plans and reviews, while the coding agent edits and executes.

01 · Secure Tunnel — the default

Prepare an existing OpenAI Tunnel ID, Runtime API Key, and official tunnel-client. Missing prerequisites are an error, never an automatic switch to Pairing.

Later: c2c start resumes the selected connection; c2c doctor checks and repairs it. Use --no-tunnel only for a local development bridge.

02 · Pairing — explicit opt-in

This profile uses Cloudflare Quick or Named transport plus OAuth. Install cloudflared first. Choosing Pairing is separate from generating a one-time code.

Register once; reuse the connector.

c2c workspace add
c2c workspace add /repo/worktree --alias review
c2c workspace set-default review
c2c workspace list

The path is positional and defaults to cwd. Mutation targets are workspace aliases/IDs. The legacy -w add spelling remains accepted, but cannot be combined with a positional path.

English by default.

c2c prefs set --language en
c2c prefs set --language zh-TW
c2c connection status --json
c2c doctor --json

Language and connection preferences belong to the installation. JSON keys and error codes remain stable; user data and third-party diagnostics are not translated.

Scopes that no longer look interchangeable.

  • start, setup, doctor and workspace-specific reads accept -w for a local root.
  • connection, stop, pair, unpair, logs and prefs are installation-wide. Compatibility -w flags are hidden and ignored.
  • unpair revokes Pairing OAuth access for every registered workspace. It is not a Secure Tunnel switch or a single-project disconnect.
  • Switch with connection use secure|pairing, then run setup or start. Failed validation leaves the previous connection profile unchanged.
